@GitHub

Work exclusively on `<owner/repository>` in PR-only mode.

Audit the live code before trusting the backlog. Compare backlog entries with current behavior, recent commits, issues, active PRs, CI, and tests. Mark items as shipped, stale, duplicated, blocked, or valid candidates based on evidence.

Select the highest-value independent candidates and create separate focused PRs. Each PR must have a clear theme, real tests, atomic commits, and a verification handoff. Update canonical backlog files only when the repository uses them and the status can be proven.

Do not combine unrelated backlog items or create filler to meet a commit target.
